# Delivery roadmap

The first release is a synthetic engineering pilot. It is not an active investment
service. Every phase has an acceptance gate; enabling a schedule alone does not
complete one.

## 1. Deterministic foundation

Local normalized ledger, independent accounting tests, matched-flow benchmark,
statement reconciliation, source-backed research records, immutable reports,
short briefing, dashboard and read-only sample gateway. Private GitHub CI uses
fictional data only. This is the implemented first slice.

## 2. Prove the phone experience

Publish the owner-private sample gateway. Connect it to a cloud ChatGPT Work chat,
retrieve the exact sample report, and ask a report-scoped follow-up. Test the
interactive widget on the phone; use the short text plus private dashboard link
where widgets are unavailable. Schedule a one-time sample retrieval, observe the
task result, and ask the user to confirm actual push delivery and its destination.
No recurring production briefings until their data pipeline is ready.

## 3. Private real-data pilot

Use a user-provided sanitized export to implement the actual Robinhood CSV
adapter. Import the complete ledger and compare against statements locally. Keep
account aliases; exclude account numbers. Check historical transfers, splits,
dividends, fees and missing history explicitly. A brokerage connection is optional
and permitted only with independently verified provider-enforced read-only scopes.

Select one licensed daily market-data provider with corporate actions and a
total-return benchmark. Validate at least one complete real valuation/benchmark
period against independent figures. Do not approximate missing quotes as zero.
Roth contribution eligibility/annual totals require verified contribution records
and filing information; current balance is not a contribution total.

## 4. Cloud engine and durable conversation context

Deploy the Python engine to private scheduled compute with an authenticated report
store. Sites Workers remain the presentation/retrieval layer. Keep personal data
out of deployment bundles and Git. Store private data in encrypted, access-limited
runtime storage with tested backup/restore and deletion policies.

Version theses, source claims, decisions and alternative portfolios. Expose
bounded research reads; add a separate explicitly scoped nonfinancial journal
write only when persistence from chat is tested. A user disagreement creates a
revision and counterargument, not a silent edit to the historical record.

## 5. Research and recommendations

Prioritize holdings' SEC filings, earnings releases, financing/dilution and major
contracts. Separate announced, contracted, energized and revenue-producing capacity.
For infrastructure compare customer concentration, funding gap, debt maturities,
capex, utilization and per-share economics. For all companies distinguish GAAP
from adjusted figures and reported facts from estimates.

Each thesis needs bear/base/bull assumptions, valuation ranges, catalysts,
invalidation criteria and an evidence timestamp. New-money suggestions must check
fresh holdings, correlated exposure, cash constraints, account suitability, and
the alternative of adding to existing holdings or a diversified benchmark.
Include opportunities outside the current AI theme when evidence warrants.

Rotation analysis compares hold/trim/new-investment alternatives, taxes and
uncertainty. Tax-lot and cross-account wash-sale modeling must precede precise
taxable-sale recommendations. Do not turn a price drop into an unsupported
"buy low" claim. Recommendations remain proposals the user executes personally.

## 6. Unattended operation

Enable every-three-calendar-day briefings, proposed 6 PM America/New_York, after
fresh cloud generation and retrieval succeed without the desktop. Record last
delivered report separately from last generated report. An independent watchdog
must detect a job that never starts and deliver a tested failure notice.

Exercise stale data, malformed imports, failed providers, revoked authentication,
duplicate tasks and missing schedules. Configure reviewed Codex maintenance PRs,
dependency/security checks and research evaluations. No autonomous deployment or
financial capability may be introduced by maintenance.

## User participation required

Only meaningful external setup needs the user: connect the private research app
in the intended cloud chat, confirm phone notification behavior, provide a secure
sample export when ready, and authorize the selected private compute/data plan
after its actual cost and permissions are known. No financial password, trading
scope, bank authorization or recurring contribution is requested.
